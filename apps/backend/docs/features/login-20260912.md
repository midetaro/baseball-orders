# ユーザーアカウント・ログイン機能設計書

## 1. 目的

ユーザーを識別し、パスワードによるログインを提供する。

個人情報は保存しない。

## 2. 前提

* Java / Spring Boot
* Spring Data JPA
* H2
* セッション認証
* パスワードはBCryptでハッシュ化する
* メールアドレス、氏名、住所、電話番号は保持しない
* パスワード再設定機能は今回対象外

## 3. 保存する情報

保存する情報は以下に限定する。

* システム内部のユーザーID
* ログイン用ユーザー名
* パスワードハッシュ
* アカウント状態
* 作成日時、更新日時

ユーザー名にも個人名やメールアドレスを入力しないよう、画面上で説明する。

## 4. usersテーブル

```sql
CREATE TABLE users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    password_hash VARCHAR(100) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);

CREATE UNIQUE INDEX uk_users_username
    ON users (username);
```

## 5. カラム定義

| カラム           | 説明                      |
| ------------- | ----------------------- |
| id            | 内部ユーザーID                |
| username      | ログイン用ユーザー名              |
| password_hash | BCryptでハッシュ化したパスワード     |
| status        | ACTIVE、LOCKED、WITHDRAWN |
| created_at    | 作成日時                    |
| updated_at    | 更新日時                    |

## 6. ユーザー固有データとの紐づけ

ユーザー固有データには、`user_id`を保持する。

```sql
CREATE TABLE user_data (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL,
    data_value VARCHAR(255) NOT NULL,
    created_at TIMESTAMP NOT NULL,

    CONSTRAINT fk_user_data_user
        FOREIGN KEY (user_id)
        REFERENCES users (id)
);
```

データ取得時は、必ずログイン中のユーザーIDを条件に使用する。

```sql
SELECT *
FROM user_data
WHERE user_id = :loggedInUserId;
```

リクエストで送られた`user_id`を認証情報として信用してはならない。

## 7. 画面・API

| メソッド | URL          | 認証 | 説明        |
| ---- | ------------ | -: | --------- |
| GET  | `/login`     | 不要 | ログイン画面    |
| POST | `/login`     | 不要 | ログイン      |
| GET  | `/users/new` | 不要 | アカウント作成画面 |
| POST | `/users`     | 不要 | アカウント作成   |
| POST | `/logout`    | 必須 | ログアウト     |
| GET  | `/user-data` | 必須 | 自分のデータ取得  |

## 8. アカウント作成

```text
1. usernameとpasswordを受け取る
2. 入力値を検証する
3. usernameの重複を確認する
4. passwordをBCryptでハッシュ化する
5. usersテーブルへ保存する
6. 登録成功を返す
```

## 9. ログイン

```text
1. usernameとpasswordを受け取る
2. usernameでユーザーを検索する
3. statusがACTIVEであることを確認する
4. BCryptでパスワードを照合する
5. 認証成功時にセッションを作成する
6. セッションへuser_idだけを保存する
```

セッションには次の情報だけを保存する。

```text
login_user_id: Long
```

## 10. セキュリティ要件

* パスワードを平文で保存しない
* パスワードをログへ出力しない
* `password_hash`をレスポンスに含めない
* ログイン成功時にセッションIDを変更する
* CSRF対策を有効にする
* CookieにHttpOnlyを設定する
* 本番環境ではSecureとSameSiteを設定する
* ログイン失敗時のメッセージを統一する
* H2コンソールを本番環境で公開しない

ログイン失敗時のメッセージ:

```text
ユーザー名またはパスワードが正しくありません。
```

## 11. H2設定

```properties
spring.datasource.url=jdbc:h2:mem:appdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
spring.jpa.hibernate.ddl-auto=validate
```

テーブル定義はFlywayなどのマイグレーションファイルで管理する。

## 12. テスト要件

* アカウントを作成できる
* 同じusernameを登録できない
* パスワードがBCryptで保存される
* 正しいパスワードでログインできる
* 間違ったパスワードでログインできない
* LOCKEDユーザーがログインできない
* ログアウト後に認証必須画面へアクセスできない
* ユーザーAがユーザーBのデータを取得できない
* パスワードやハッシュ値がレスポンス・ログに含まれない

## 13. 制約

メールアドレスを保持しないため、パスワードを忘れた場合の本人確認や自動リセットはできない。

パスワード再設定が必要になった場合は、将来的に以下のいずれかを追加する。

* 管理者による手動リセット
* リセット用ワンタイムコード
* 外部認証サービス
