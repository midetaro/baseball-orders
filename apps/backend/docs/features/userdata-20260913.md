# Design Change: Allow Anonymous Simulation Execution

## Change Summary

認証済みユーザー以外もシミュレーションを実行できるようにする。

ただし、シミュレーション結果の統計情報をDBへ保存するのは、認証済みユーザーに限定する。

## Authentication Rules

| 操作           | 未認証ユーザー | 認証済みユーザー |
| ------------ | ------: | -------: |
| シミュレーション実行   |      許可 |       許可 |
| シミュレーション結果表示 |      許可 |       許可 |
| 統計情報のDB保存    |      不可 |       許可 |
| 自分の統計情報取得    |      不可 |       許可 |

## `simulations`テーブル変更

未認証ユーザーのシミュレーションも管理できるよう、`user_id`をNULL許可に変更する。

```sql
CREATE TABLE simulations (
    simulation_id VARCHAR(100) PRIMARY KEY,
    user_id BIGINT NULL,
    status VARCHAR(20) NOT NULL,
    created_at TIMESTAMP NOT NULL,
    completed_at TIMESTAMP NULL,

    CONSTRAINT fk_simulations_user
        FOREIGN KEY (user_id)
        REFERENCES users (id)
);
```

## `simulation_statistics`テーブル

統計情報は認証済みユーザー専用のため、`user_id`はNULL禁止とする。

`simulation-result` SQSメッセージの`statistics`には、全試合の`averageScore`（平均得点）、
`medianScore`（中央値得点）、`maximumScore`（最大得点）が含まれる。各試合の`results`には
`score`と`runs`が含まれるが、これは試合ごとの結果であり、ホーム・アウェーの集計値ではない。
そのため、このテーブルにはキューで受信する集計済みの3統計値を保存する。

```sql
CREATE TABLE simulation_statistics (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    simulation_id VARCHAR(100) NOT NULL,
    user_id BIGINT NOT NULL,
    average_score DOUBLE PRECISION NOT NULL,
    median_score DOUBLE PRECISION NOT NULL,
    maximum_score INT NOT NULL,
    created_at TIMESTAMP NOT NULL,

    CONSTRAINT fk_simulation_statistics_simulation
        FOREIGN KEY (simulation_id)
        REFERENCES simulations (simulation_id),

    CONSTRAINT fk_simulation_statistics_user
        FOREIGN KEY (user_id)
        REFERENCES users (id),

    CONSTRAINT uk_simulation_statistics_simulation
        UNIQUE (simulation_id)
);
```

## シミュレーション開始処理

```text
1. シミュレーションリクエストを受信
2. ログイン済みであれば、セッションからuser_idを取得
3. 未ログインであれば、user_id = NULLとする
4. simulation_idを生成
5. simulationsへ保存
6. SQSへシミュレーション要求を送信
7. simulation_idをレスポンスする
```

`user_id`をリクエストボディやURLから取得してはならない。

## 結果受信処理

```text
1. simulation-resultから結果を受信
2. simulation_idでsimulationsを検索
3. simulations.user_idを取得
4. 結果をSimulationResultへ変換
5. user_idがNULLでない場合のみ統計情報を保存
6. simulations.statusをCOMPLETEDへ変更
7. simulations.completed_atを設定
8. 既存の結果返却処理を完了する
```

### 処理分岐

```text
IF simulations.user_id IS NOT NULL
THEN
    simulation_statisticsへ保存する
ELSE
    simulation_statisticsへ保存しない
END IF
```

未認証ユーザーの結果は、シミュレーション実行中のレスポンスまたは`simulation_id`による一時的な結果取得で表示する。

## 認証要件

### シミュレーション実行

```text
POST /simulations
Authentication: optional
```

### シミュレーション結果取得

```text
GET /simulations/{simulationId}
Authentication: optional
```

ただし、他人の結果を自由に参照できないよう、次のいずれかを実装する。

* 結果返却をシミュレーション実行直後のリクエストに限定する
* 推測困難なランダムな`simulation_id`を使用する
* 結果取得用の一時トークンを発行する

単純な連番IDを公開してはならない。

### 統計情報取得

```text
GET /simulation-statistics
Authentication: required
```

```text
GET /simulation-statistics/{simulationId}
Authentication: required
```

統計情報取得時は、必ず認証済みユーザーのIDを検索条件に含める。

```sql
SELECT *
FROM simulation_statistics
WHERE simulation_id = :simulationId
  AND user_id = :authenticatedUserId;
```

## ドメインモデル

```java
public class Simulation {

    private String simulationId;

    // 未認証の場合はnull
    private Long userId;

    private SimulationStatus status;
}
```

`SimulationStatistics`の`userId`は必須とする。

```java
public class SimulationStatistics {

    private String simulationId;
    private Long userId;
    private double averageScore;
    private double medianScore;
    private int maximumScore;
    private LocalDateTime createdAt;
}
```

## 保存ルール

| user_id   | simulations保存 | simulation_statistics保存 |
| --------- | ------------: | ----------------------: |
| NULL      |          保存する |                   保存しない |
| 有効なユーザーID |          保存する |                    保存する |

## トランザクション

結果受信処理は1トランザクションで実行する。

```java
@Transactional
public void saveSimulationResult(
        String simulationId,
        SimulationResult result
) {
    Simulation simulation =
        simulationRepository.findBySimulationId(simulationId)
            .orElseThrow();

    if (simulation.getUserId() != null) {
        simulationStatisticsRepository.save(
            SimulationStatistics.create(
                simulation.getSimulationId(),
                simulation.getUserId(),
                result.statistics().averageScore(),
                result.statistics().medianScore(),
                result.statistics().maximumScore()
            )
        );
    }

    simulation.complete();
}
```

## テスト要件

### 未認証ユーザー

* 未認証でもシミュレーションを開始できる
* `simulations.user_id`がNULLで保存される
* 結果を画面へ返却できる
* `simulation_statistics`に保存されない
* 統計情報APIへアクセスできない

### 認証済みユーザー

* 認証済みでシミュレーションを開始できる
* `simulations.user_id`にログインユーザーIDが保存される
* 結果が`simulation_statistics`へ保存される
* 自分の統計情報を取得できる
* 他ユーザーの統計情報を取得できない

### 共通

* 同じ`simulation_id`の結果を二重保存しない
* シミュレーター側に変更を加えない
* 個人情報を追加保存しない

## Acceptance Criteria

```text
1. 未認証ユーザーがシミュレーションを実行できる
2. 認証済みユーザーがシミュレーションを実行できる
3. 未認証ユーザーの結果はDB統計情報へ保存されない
4. 認証済みユーザーの結果はDB統計情報へ保存される
5. 認証済みユーザーは自分の統計情報だけ取得できる
6. シミュレーターは変更しない
7. 個人情報は保存しない
8. 重複したSQSメッセージで二重登録されない
9. 既存のシミュレーション結果返却処理を維持する
```
