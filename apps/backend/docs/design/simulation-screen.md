# シミュレーション画面仕様

## 基本情報

| 項目 | 仕様 |
|---|---|
| 目的 | 1番から9番までの選手能力・性格・戦術を指定し、複数試合の得点結果を比較できるようにする |
| URL | `GET /` |
| テンプレート | `apps/backend/infrastructure/src/main/resources/templates/simulation.html` |
| サービス名 | 打順監督 |
| ブラウザタイトル | 打順監督 |
| 関連画面 | 「シミュレーションの仕組み」リンクから `GET /simulation-guide` へ遷移 |

画面上で選手名は入力させない。各行を固定表示の「1番」から「9番」として扱い、APIにも名前を送信しない。

## 画面構成

画面は「打順入力」と「試合結果」の2領域で構成する。初期表示時から見出し、入力ラベル、結果ラベルを隠さない。

デスクトップでは2領域を横並びにし、打順入力へ広めの幅を割り当てる。画面幅が980px以下の場合は縦積みにする。入力表は必要な横幅を維持し、領域内で横スクロールさせる。760px以下では結果見出し、統計、グラフ、戦術の値が切れないように再配置する。

## 打順入力

### 行と入力項目

9行を固定表示する。各行は次の項目をこの順で持つ。

| 表示項目 | APIプロパティ | 入力形式 | ブラウザ上の範囲 | 備考 |
|---|---|---|---|---|
| 打順 | 送信しない | 固定ラベル | 1番〜9番 | 配列内の位置を打順として扱う |
| 出塁率 | `hit_average` | 数値、小数第2位まで | 0.01〜0.60 | フォーカスを外すと小数第2位まで表示する |
| 長打率 | `sluggish` | 数値、小数第2位まで | 0.10〜0.60 | フォーカスを外すと小数第2位まで表示する |
| バント成功率 | `bunt_success_rate` | 数値、小数第2位まで | 0.00〜0.95 | バントが「しない」の間は入力不可。値は保持する |
| 盗塁成功率 | `steal_success_rate` | 数値、小数第2位まで | 0.10〜0.90 | 盗塁が「しない」の間は入力不可。値は保持する |
| 性格 | `personality` | 選択 | 後述の4種類 | 初期値は全員 `DEFAULT` |
| バント | `bunt_enabled` | トグル | する／しない | 選手単位で切り替える |
| 盗塁 | `steal_enabled` | トグル | する／しない | 選手単位で切り替える |

小数点から入力を始めた場合は先頭へ `0` を補う。必須値が空、範囲外、または小数第3位以下を含む間は実行ボタンを無効にし、入力条件をフィードバック領域へ表示する。

### 性格

画面表示とAPI値の対応は次のとおり。

| 画面表示 | API値 |
|---|---|
| 標準 | `DEFAULT` |
| ブンブン丸 | `EAGER_SLUGGISH` |
| 盗塁重視 | `EAGER_STEAL` |
| バント重視 | `EAGER_BUNT` |

性格がシミュレーションへ与える意味は[シミュレーションの仕組み画面仕様](./simulation-guide-screen.md)に定義する。

### 一括操作

- 「全員バント」: 全員が「する」なら全員を「しない」にする。それ以外は全員を「する」にする。
- 「全員盗塁」: 全員が「する」なら全員を「しない」にする。それ以外は全員を「する」にする。
- 「性格を初期化」: 全員の性格を「標準」にする。能力値や戦術設定は変更しない。

### 実行可能状態

全9人の全入力が有効な場合だけ「SIMULATIONを実行」を押せる。実行中は二重送信を防ぐため、実行ボタン、能力値、性格、個別・一括の戦術操作、性格初期化を無効にする。

フィードバック領域は状態に応じて次を表示する。

| 状態 | 表示内容 |
|---|---|
| 入力が有効 | `準備完了。シミュレーションを実行できます。` |
| 入力が無効 | 許容範囲と小数第2位までの入力を案内 |
| 実行中 | `シミュレーション中…` |
| 成功 | `試合終了：{gameCount}試合` |
| 0試合 | `試合結果はありません。` |
| 失敗 | APIの `error`、`message`、または既定の失敗文言 |

## シミュレーションAPI

「SIMULATIONを実行」で `POST /simulations` を呼び出す。`Content-Type` は `application/json` とし、9人を打順どおりの配列で送信する。

```json
[
  {
    "hit_average": 0.40,
    "sluggish": 0.35,
    "bunt_success_rate": 0.8,
    "steal_success_rate": 0.8,
    "bunt_enabled": true,
    "steal_enabled": true,
    "personality": "DEFAULT"
  }
]
```

成功レスポンスは次の表示用データを使用する。

```json
{
  "simulationId": "UUID",
  "statistics": {
    "averageScore": 0.0,
    "medianScore": 0.0,
    "maximumScore": 0,
    "gameCount": 0,
    "scoreDistribution": { "0": 0 },
    "homeRunCount": 0,
    "soloHomeRunCount": 0,
    "twoRunHomeRunCount": 0,
    "threeRunHomeRunCount": 0,
    "grandSlamCount": 0,
    "buntCount": 0,
    "stealCount": 0,
    "buntFailureCount": 0,
    "stealFailureCount": 0
  }
}
```

## 試合結果

結果領域は次の3グループで表示する。

### 得点サマリー

- 試合数、平均得点、中央値得点、最大得点を数値表示する。
- 得点分布は横軸を得点、縦軸を全試合に対する割合とするヒストグラムで表示する。
- 各棒へ試合数の文字は重ねない。アクセシブル名には `{得点}点: {割合}%` を設定する。
- 縦軸は25%単位とし、最大の棒を収められる25%刻みの上限へ調整する。最低上限は25%とする。

### 本塁打の内訳

- 本塁打総数を数値表示する。
- ソロ、ツーラン、スリーラン、満塁を、総本塁打数を分母とした割合の積み上げ棒で表示する。
- 棒の中には文字を表示せず、色、種別、割合を凡例に表示する。
- 件数が0の種別は棒と凡例の両方から除外する。
- 総本塁打数が0の場合は「本塁打なし」を表示する。

### 戦術の成否

成功バント、失敗バント、成功盗塁、失敗盗塁を同一スケールの比較棒で表示する。各項目の数値は棒の外へ分離し、`{総件数} ({1試合あたり件数}/試合)` の形式で表示する。

## 結果共有

「結果を共有」は次のテキストを対象とする。

```text
打順監督の結果
平均得点: {averageScore}
中央値得点: {medianScore}
最大得点: {maximumScore}
```

- Web Share APIを利用できる場合は、タイトルを「打順監督の結果」として共有する。
- 利用できない場合はクリップボードへコピーする。
- 成功時は共有またはコピーの完了をフィードバック領域へ表示する。
- ユーザーが共有をキャンセルした場合はエラー表示しない。それ以外の失敗では「共有できませんでした。」と表示する。

## 実装上の既知事項

ブラウザは出塁率を0.60まで許可する一方、backendの `PlayerData` は現在0.400を上限として検証している。0.400を超える入力はブラウザ上では実行可能でも、API側で拒否される。仕様変更時は画面とbackendの許容範囲を同時に確認すること。
