# シミュレーション画面仕様

## 基本情報

| 項目 | 仕様 |
|---|---|
| 目的 | 1番から9番までの選手能力・性格・戦術を指定し、複数試合の得点結果を比較できるようにする |
| URL | `GET /`、`GET /large-scale`（同じ画面） |
| テンプレート | `apps/backend/infrastructure/src/main/resources/templates/simulation.html` |
| サービス名 | 打順監督 |
| ブラウザタイトル | 打順監督 |
| 関連画面 | 「シミュレーションの仕組み」から `GET /simulation-guide`、「1試合実行はこちら」から `GET /single-game` へ遷移 |

画面上で選手名は入力させない。各行を固定表示の「1番」から「9番」として扱い、APIにも名前を送信しない。

## 画面構成

画面は「打順入力」と「試合結果」の2画面で構成し、画面上部の切り替えタブ（`1 打順入力` / `2 試合結果`）で同一URL内を切り替える。2画面を同時に表示しない。

- 初期表示は打順入力画面のみを表示し、試合結果タブは結果が得られるまで選択できない。
- シミュレーションが成功すると試合結果画面へ切り替え、結果画面の見出し下に `試合終了：{gameCount}試合` を表示する。
- 試合結果画面の「打順を編集する」または打順入力タブで入力画面へ戻る。入力値は保持され、そのまま再実行できる。結果が得られた後は試合結果タブから前回の結果へ戻れる。
- 実行中は二重操作を防ぐため、タブと「打順を編集する」を無効にする。

PC幅（761px以上）では打順入力画面をコンパクトな入力カードとして中央に置き、試合結果画面は全幅で得点サマリーの下に4つの内訳（安打・本塁打・バント・盗塁）を2列に並べる。760px以下でも打順入力はPC幅と同じく列見出し行を表示し、打者ごとに一行で入力欄を横に並べる。このときバント・盗塁の切り替えは列見出しと重複する項目名を省略して「する」「しない」だけを表示し、読み上げ用には項目名を含めた名前を付ける。あわせて結果見出し、統計、グラフの値が切れないように再配置する。

配色は紙のような生成り色を地色とし、モスグリーン（主要操作・強調）、セージ、テラコッタ（共有・失敗系）、オーカー、くすんだ青を内訳の色に使うアースカラー基調とする。

## 打順入力

### 行と入力項目

9行を固定表示する。各行は次の項目をこの順で持つ。

| 表示項目 | APIプロパティ | 入力形式 | ブラウザ上の範囲 | 備考 |
|---|---|---|---|---|
| 打順 | 送信しない | 固定ラベル | 1番〜9番 | 配列内の位置を打順として扱う |
| 打率 | `hit_average` | 数値、小数第2位まで | 0.01〜0.60 | フォーカスを外すと小数第2位まで表示する |
| 長打率 | `sluggish` | 数値、小数第2位まで | 0.10〜0.60 | フォーカスを外すと小数第2位まで表示する |
| 性格 | `personality` | 選択 | 後述の4種類 | 初期値は全員 `DEFAULT` |
| バント | `bunt_enabled` | トグル | する／しない | 選手単位で切り替える |
| 盗塁 | `steal_enabled` | トグル | する／しない | 選手単位で切り替える |

小数点から入力を始めた場合は先頭へ `0` を補う。必須値が空、範囲外、または小数第3位以下を含む間は実行ボタンを無効にし、入力条件をフィードバック領域へ表示する。

### 初期値

| 打順 | 打率 | 長打率 | 性格 | バント | 盗塁 |
|---:|---:|---:|---|---|---|
| 1番 | 0.35 | 0.35 | 標準 | する | する |
| 2番 | 0.35 | 0.35 | 標準 | する | する |
| 3番 | 0.35 | 0.50 | 標準 | しない | しない |
| 4番 | 0.35 | 0.40 | 標準 | しない | しない |
| 5番 | 0.35 | 0.40 | 標準 | しない | しない |
| 6番 | 0.33 | 0.40 | 標準 | する | する |
| 7番 | 0.29 | 0.40 | 標準 | する | する |
| 8番 | 0.28 | 0.40 | 標準 | する | する |
| 9番 | 0.27 | 0.40 | 標準 | する | する |

バント・盗塁の成功率は入力項目ではなく、Simulator の設定値（`simulation.rule.*`）を全選手共通で使う。

### 性格

画面表示とAPI値の対応は次のとおり。

| 画面表示 | API値 |
|---|---|
| 標準 | `DEFAULT` |
| 長距離砲 | `EAGER_SLUGGISH` |
| 盗塁重視 | `EAGER_STEAL` |
| バント重視 | `EAGER_BUNT` |

性格がシミュレーションへ与える意味は[シミュレーションの仕組み画面仕様](./simulation-guide-screen.md)に定義する。

### 一括操作

- 「全員バント」: 全員が「する」なら全員を「しない」にする。それ以外は全員を「する」にする。
- 「全員盗塁」: 全員が「する」なら全員を「しない」にする。それ以外は全員を「する」にする。
- 「性格を初期化」: 全員の性格を「標準」にする。能力値や戦術設定は変更しない。

### 実行可能状態

全9人の全入力が有効な場合だけ「SIMULATIONを実行」を押せる。実行中は二重送信を防ぐため、実行ボタン、能力値、性格、個別・一括の戦術操作、性格初期化を無効にする。

フィードバック領域は状態に応じて次を表示する。

| 状態 | 表示内容 |
|---|---|
| 入力が有効 | `準備完了。シミュレーションを実行できます。` |
| 入力が無効 | 許容範囲と小数第2位までの入力を案内 |
| 実行中 | `シミュレーション中…` |
| 成功 | 試合結果画面へ切り替え、結果画面に `試合終了：{gameCount}試合` を表示 |
| 0試合 | 試合結果画面へ切り替え、結果画面に `試合結果はありません。` を表示 |
| 失敗 | APIの `error`、`message`、または既定の失敗文言 |

## シミュレーションAPI

「SIMULATIONを実行」で `POST /simulations` を呼び出す。`Content-Type` は `application/json` とし、9人を打順どおりの配列で送信する。

```json
[
  {
    "hit_average": 0.40,
    "sluggish": 0.35,
    "bunt_enabled": true,
    "steal_enabled": true,
    "personality": "DEFAULT"
  }
]
```

成功レスポンスは次の表示用データを使用する。

```json
{
  "simulationId": "UUID",
  "statistics": {
    "averageScore": 0.0,
    "medianScore": 0.0,
    "maximumScore": 0,
    "gameCount": 0,
    "scoreDistribution": { "0": 0 },
    "hitCount": 0,
    "singleHitCount": 0,
    "doubleHitCount": 0,
    "tripleHitCount": 0,
    "homeRunCount": 0,
    "soloHomeRunCount": 0,
    "twoRunHomeRunCount": 0,
    "threeRunHomeRunCount": 0,
    "grandSlamCount": 0,
    "buntCount": 0,
    "stealCount": 0,
    "buntFailureCount": 0,
    "stealFailureCount": 0,
    "advancingBuntCount": 0,
    "squeezeBuntCount": 0,
    "advancingBuntFailureCount": 0,
    "squeezeBuntFailureCount": 0,
    "stealToSecondCount": 0,
    "stealToThirdCount": 0
  },
  "transitions": []
}
```

## 試合結果

結果領域は得点サマリーと、安打・本塁打・バント・盗塁の4つの内訳に分けて表示する。各内訳の見出しは折りたたみできる。

### 得点サマリー

- 試合数、平均得点、中央値得点、最大得点を数値表示する。
- 得点分布は横軸を得点、縦軸を全試合に対する割合とするヒストグラムで表示する。
- 各棒へ試合数の文字は重ねない。アクセシブル名には `{得点}点: {割合}%` を設定する。
- 縦軸は25%単位とし、最大の棒を収められる25%刻みの上限へ調整する。最低上限は25%とする。

### 安打の内訳

- 総安打数を数値表示する。
- 一塁打、二塁打、三塁打、本塁打を、表示対象の内訳件数合計を分母とした割合の積み上げ棒で表示する。
- 棒の中には文字を表示せず、色、種別、割合を凡例に表示する。
- 件数が0の種別は棒と凡例の両方から除外し、内訳件数の合計が0の場合は「安打なし」を表示する。

### 本塁打の内訳

- 本塁打総数を数値表示する。
- ソロ、ツーラン、スリーラン、満塁を、表示対象の内訳件数合計を分母とした割合の積み上げ棒で表示する。
- 棒の中には文字を表示せず、色、種別、割合を凡例に表示する。
- 件数が0の種別は棒と凡例の両方から除外する。
- 内訳件数の合計が0の場合は「本塁打なし」を表示する。
- APIの本塁打総数と内訳件数合計が一致しない場合も、総数はそのまま表示し、積み上げ棒の割合には内訳件数合計を使用する。

### バントの内訳

- 成功バント総数と失敗バント総数を数値表示する。
- 進塁成功、スクイズ成功、進塁失敗、スクイズ失敗を、表示対象の内訳件数合計を分母とした割合の積み上げ棒で色分けして表示する。
- 棒の中には文字を表示せず、色、種別、割合を凡例に表示する。
- 件数が0の種別は棒と凡例の両方から除外し、内訳件数の合計が0の場合は「バントなし」を表示する。
- APIの成功・失敗総数と内訳件数合計が一致しない場合も、各総数はそのまま表示し、積み上げ棒の割合には内訳件数合計を使用する。

### 盗塁の内訳

- 成功盗塁総数と失敗盗塁総数を数値表示する。
- 二盗成功、三盗成功、失敗を、表示対象の内訳件数合計を分母とした割合の積み上げ棒で色分けして表示する。
- 棒の中には文字を表示せず、色、種別、割合を凡例に表示する。
- 件数が0の種別は棒と凡例の両方から除外し、内訳件数の合計が0の場合は「盗塁なし」を表示する。
- APIの成功・失敗総数と内訳件数合計が一致しない場合も、各総数はそのまま表示し、積み上げ棒の割合には内訳件数合計を使用する。

## 結果共有

「結果を共有」は次のテキストを対象とする。

```text
打順監督の結果
平均得点: {averageScore}
中央値得点: {medianScore}
最大得点: {maximumScore}
```

- Web Share APIを利用できる場合は、タイトルを「打順監督の結果」として共有する。
- 利用できない場合はクリップボードへコピーする。
- 成功時は共有またはコピーの完了を試合結果画面の見出し下へ表示する。
- ユーザーが共有をキャンセルした場合はエラー表示しない。それ以外の失敗では「共有できませんでした。」と表示する。

## 実装上の既知事項

- backendの `PlayerData` は打率・長打率を0.000〜1.000で検証し、画面の入力範囲（打率0.01〜0.60、長打率0.10〜0.60）はブラウザ側だけで制限している。
- 打線全体の平均打率・平均長打率の上限（`baseball-orders.simulation.maximum-average-hit-average` / `maximum-average-sluggish`、既定0.35 / 0.40）はbackendの `SimulationCoordinator` だけが検証する。画面では上限超過を事前に案内せず、超過時はAPIが500を返し、既定の失敗文言として `Internal Server Error` が表示される。
- 仕様変更時は画面とbackendの許容範囲を同時に確認すること。
