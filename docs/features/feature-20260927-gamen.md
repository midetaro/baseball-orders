シミュレーション画面のレイアウトを改善してください。

## 目的

現在、入力項目を含むカード状の領域で、次の問題が発生しています。

- 画面幅や文字量によってカードや入力欄の幅が不自然に変わる
- ラベルと入力欄の開始位置が揃っていない
- 文字サイズ、行間、要素間の余白に統一感がない
- input、select、buttonの高さが揃っていない
- バリデーションエラーの表示によってレイアウトが上下に動く
- PC表示とスマートフォン表示のバランスが悪い

既存の機能や画面内容を変更せず、文字・入力欄・余白が規則的に配置された、安定感のある画面に修正してください。

## 実装方針

### 1. 既存実装の確認

修正前に、対象画面に関係する以下のファイルを確認してください。

- Thymeleafテンプレート
- CSSファイル
- JavaScriptファイル
- 共通レイアウトおよび共通スタイル
- 入力フォームとバリデーションエラーの表示箇所

既存のスタイルを再利用できる場合は、新しい定義を重複して追加しないでください。

### 2. カード幅の安定化

カードを完全な固定幅にはせず、画面幅に追従しながら一定の最大幅を持つようにしてください。

実装の目安は次のとおりです。

```css
.simulation-card {
    width: min(100%, 720px);
    margin-inline: auto;
    padding: 24px;
    box-sizing: border-box;
}
```

ただし、クラス名や最大幅は既存画面の構造に合わせて調整してください。

### 3. 入力項目の整列

PC表示ではCSS Gridを使用し、ラベルと入力欄を同じ列に揃えてください。

```css
.form-grid {
    display: grid;
    grid-template-columns: 140px minmax(0, 1fr);
    gap: 16px 24px;
    align-items: start;
}
```

ラベルの文字数が異なっても、すべての入力欄の開始位置が揃うようにしてください。

Flexboxの入れ子や、要素ごとの個別な`margin`による位置調整は、必要最小限にしてください。

### 4. 余白と文字サイズの統一

CSS変数を使用し、文字サイズと余白の段階を定義してください。

```css
:root {
    --space-xs: 4px;
    --space-sm: 8px;
    --space-md: 16px;
    --space-lg: 24px;

    --font-sm: 0.875rem;
    --font-md: 1rem;
    --font-lg: 1.25rem;

    --line-height-normal: 1.6;
}
```

既に同等のCSS変数やデザインルールが存在する場合は、既存定義を優先してください。

余白は原則として、4pxまたは8pxを基準とした値に統一してください。

### 5. 入力部品の統一

`input`、`select`、`button`について、文字、内側余白、高さ、ボックスサイズを統一してください。

```css
input,
select,
button {
    min-height: 44px;
    padding: 8px 12px;
    font: inherit;
    line-height: 1.4;
    box-sizing: border-box;
}
```

入力欄には原則として次の指定を行ってください。

```css
.form-input {
    width: 100%;
    min-width: 0;
}
```

ただし、チェックボックスやラジオボタンには通常の入力欄と同じ高さを強制しないでください。

### 6. エラー表示によるレイアウト変動の防止

バリデーションエラーの表示・非表示によって、入力欄やボタンの位置が大きく動かないようにしてください。

必要に応じて、各入力項目にエラー表示用の領域を確保してください。

```css
.form-field {
    display: grid;
    grid-template-rows: auto minmax(20px, auto);
    gap: 4px;
}

.field-error {
    min-height: 20px;
    font-size: 0.75rem;
}
```

既存のThymeleafバリデーション表示は維持してください。

### 7. レスポンシブ対応

PCではラベルと入力欄を横並びにし、画面幅が狭い場合は縦並びに切り替えてください。

```css
@media (max-width: 600px) {
    .simulation-card {
        padding: 16px;
    }

    .form-grid {
        grid-template-columns: 1fr;
        gap: 8px;
    }
}
```

スマートフォン表示で横スクロールが発生しないことを確認してください。

### 8. 変更時の制約

以下は変更しないでください。

- フォームの送信先
- `name`、`id`、`th:field`など、バックエンドとの連携に必要な属性
- バリデーションの条件
- JavaScriptが参照している識別子
- シミュレーションの処理内容
- 表示する入力項目や結果項目
- 既存の画面遷移

HTML構造の変更は、レイアウト改善に必要な最小限にしてください。

BootstrapなどのCSSフレームワークが導入されていない場合、この修正だけを目的に新しいフレームワークを追加しないでください。

固定の`height`を多用せず、文字が折り返された場合にも内容が収まるようにしてください。

## 作業手順

1. 対象画面と関連するCSSを確認する
2. レイアウトが不揃いになる原因を特定する
3. 修正方針を簡潔に説明する
4. HTMLとCSSを必要最小限修正する
5. PC幅、タブレット幅、スマートフォン幅で表示を確認する
6. 既存の入力、送信、エラー表示が動作することを確認する
7. テストまたはビルドを実行する
8. 変更したファイルと確認結果を報告する

## 完了条件

以下をすべて満たした状態を完了とします。

- カードが画面中央に配置され、極端に拡大・縮小しない
- 同じ種類のカードの横幅と内側余白が統一されている
- ラベルと入力欄の位置が規則的に揃っている
- 文字サイズと行間に一貫性がある
- input、select、buttonの高さが揃っている
- 長い文字があってもカードからはみ出さない
- エラー表示による大きなレイアウト移動がない
- スマートフォンで自然な縦並びになる
- 横スクロールが発生しない
- 既存のフォーム送信とシミュレーション機能が壊れていない
- 不要な依存関係が追加されていない

作業完了後、次の内容を報告してください。

- レイアウトが崩れていた主な原因
- 変更したファイル
- 実施した修正
- 動作確認した画面幅
- 実行したテストまたはビルド
- 残っている課題
